# pingscreen 0.1.2 验证记录

**验证日期：** 2026-10-13  
**环境：** Windows 11 x64，单显示器 1920×1080，缩放 100%，HDR 开启。Windows SDR 白电平 3850（相对于标准 80 nit 白电平为 3.85 倍）。

## 已验证

### 自动检查

- TypeScript 类型检查通过。
- 应用自动测试 37 项通过，覆盖四/五项轮盘、边缘取消、选框裁界、截图像素转换、负坐标与 150%/200% 缩放换算、协议解析、会话失效、流式响应、系统密钥保存、截图工作进程分段二进制协议/崩溃重试/启动失败、8 MiB 图片分段拼接、细节裁图、点/条模式增量与反向切换及提示词隔离。
- 复用的原生输入助手 C++ 测试 430 项通过，包括堵塞读取时合并 10000 条移动仍保留起手与松开的顺序，以及轮盘期间滚轮的吞入/转发、正常滚轮放行、取消/暂停后的滚轮、带符号增量和模拟协议。
- HDR 颜色测试 11 项通过，验证浮点解码、SDR 白电平、sRGB gamma、亮部色相、异常值和 alpha；1.0/2.0/3.85 白电平下穷举全部 65536 种半精度值组合，对比查表与参考转换结果一致。

### 应用流程

- Electron 完整流程测试通过：设置页和隔离 preload、截图期间快速松手、整屏定位与额外细节图请求、流式回答、同截图追问、框选后四项意图、自定义问题、停止生成、截图取消和新手势取消旧请求。额外验证图片编码前已显示轮盘、等待期间不渲染空截图、同一扇区 1000 次移动不重复发送刷新、Markdown 加粗/列表/代码/链接和禁止自动加载远程图片。
- 翻译点/条完整流程通过：四/五项轮盘、截图完成前滚轮切换后立即松开、高精度增量累计、反向切换、非翻译扇区不切换、离开再进入保留模式、新手势恢复点模式、取消不复活、追问沿用条模式。点与条请求的图片载荷和定位点完全相同，只改变指令。模式更新包小于 160 字节，不含图片字段。
- Electron 离屏渲染预览已检查：设置、自定义轮盘、框选意图轮盘和回答卡片。
- 真实 DXGI 截图验证得到 1920×1080、R16G16B16A16_FLOAT，正确识别 HDR 状态和 SDR 白电平。实测仅保存元数据和耗时，没有保存真实桌面图片或调用用户模型。

### 安装包

- Windows x64 NSIS 安装包已生成，包含独立 hook-helper.exe、capture-helper.exe 和应用许可证。
- 0.1.2 安装包实测 99.4 MiB，解包目录 332.5 MiB；此前 0.1.1 为 107.7 MiB / 379.6 MiB，分别减少约 7.7% / 12.4%。打包目录仅保留 en-US.pak、zh-CN.pak；两个原生助手与当前构建的 SHA256 分别一致。

## 性能记录

0.1.1 性能对比记录：同机暖启动的最后一组 5 次抓取，画面取得约 11.7–13.9 ms，完整 PNG 准备约 56.5–65.6 ms；旧路径包含固定 90 ms 等待的 3 次截图/编码约 579–677 ms。新轮盘在画面取得后即可显示，实际视觉延迟还包含 IPC、浏览器绘制和显示器刷新，不能把抓取时间视为端到端延迟。此前测量中 DXGI 重新初始化曾达到约 200 ms，首次启动、驱动恢复和静止画面不保证上述暖启动速度。0.1.2 未重新测量端到端轮盘延迟。

轮盘主资源从约 672 KB 压缩到约 238 KB；Markdown 的约 159 KB 压缩资源独立加载。多屏坐标只在显示器变化时更新，轮盘只在扇区变化时刷新，PNG 和模型定位图在追问中复用。

0.1.2 PNG 分段传输改为一次分配、按偏移写入，减少图片传输中的重复整图复制；打包语言资源限定为 zh-CN/en-US。仍值得后续优化的地方包括：把标注图/裁图的 PNG 编码移出主进程、长回答的 UI 增量更新、不同显示器/驱动的端到端耗时测量。
