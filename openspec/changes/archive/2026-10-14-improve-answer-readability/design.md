# Design

## Context

动机和已确认产品范围见 proposal.md；可验收的行为见 specs/answer-reading/spec.md。2026-10-14 用户确认 Q1–Q4 并完成字号与第一版简约卡片，随后要求进一步缩窄卡片、动态增高及 X 关闭。本文件替代固定 16:10 和顶部无关闭按钮的方案；本轮仅更新规划，新增调整尚未进入代码。

现有实现：

- `src/renderer/Answer.tsx` 渲染 Markdown；`main.tsx` 的 Card 管理逐轮问答、生成状态、复制和输入区。截图已不展示，但仍用于模型上下文。
- 回答字号已通过局部变量应用，默认 16px、范围 14–24px；行高 1.8，标题、代码和表格按正文比例调整，输入框固定 14px。
- 本轮起点为已实现的 640 × 400 卡片，工作区不足时同比例缩小；外边框 1px、颜色 `#e6e9ee`、圆角 12px。顶部只有品牌，关闭依赖 Esc；窗口不可由用户手工缩放。
- 共享 `answerCardSize` 用于创建窗口和显示会话；现有固定比例尺寸逻辑需被内容高度方案替代。主进程已有关闭命令及会话标识校验。
- 现有 SettingsStore 支持部分设置更新、归一化和本地保存；设置页有自动保存队列，能隔离未保存的模型草稿。
- 打开设置和保存设置均会结束当前会话。用户已确认沿用此流程，自动保存字号并在下一张回答卡片生效，重启后保留。
- 回答窗口通过 CardState 接收会话字号快照，不接收完整设置。设置读写接口仍仅授权设置窗口。
- 底部常驻提示已删除，动态复制、错误等反馈仍按需显示。高度测量需要包括这些反馈，避免挤走输入框。
- `docs/media/answer-card-minimal.png` 与 `answer-card-empty.png` 是上一版固定尺寸的验证截图；它们不代表本次动态高度、边框和关闭按钮的最终效果。

本变更跨设置存储、窗口状态、回答排版和交互验证，且存在需要明确区分的设计候选，因此需要 design.md。

## Goals / Non-Goals

**Goals:**

- 用现有设置通路保存单一回答字号参数；只向回答窗口传递所需的阅读参数。
- 将字号应用限定在回答渲染区域，协调 Markdown 内的文字比例和滚动行为。
- 以已确认删除清单改善视觉层级，避免误删内容、状态或操作反馈。
- 使用本地固定回答样例验证排版，不把模型生成内容的变化当作视觉验收证据。
- 让内容的自然高度驱动真实窗口尺寸，控制更新频率，保持会话隔离和屏幕边缘可达性。

**Non-Goals:**

- 不实现原会话内的实时字号调整，不改变会话生命周期。
- 不因本需求放开回答窗口的设置读写权限。
- 不把回答字号参数扩大到轮盘、设置页、输入框或整个应用；输入框使用独立固定 14px。
- 不启用用户拖动缩放或新增主题；不再维持固定 16:10，也不增加动态高度开关或新的高度设置项。

## Decisions

### 1. 沿用设置页自动保存，下一张卡片生效（已确认产品行为）

字号修改复用设置页的部分更新和自动保存流程，不新增卡片内控件，也不增加一个必须点击的保存按钮。原会话按既有设置流程结束，新会话采用已保存值。

备选方案是让原会话保留并立即更新字号，这会涉及关闭逻辑、配置事件和生成中布局；用户本轮选择沿用现有流程，因此不采用。

### 2. 独立字号字段和归一化逻辑（已实现，保留）

字段名为 `answerFontSize`，类型为数值，单位为 CSS px。在共享设置类型、默认值和 SettingsStore.normalize 中处理；设置页将其纳入 ImmediateSettings，并通过已有队列单独提交字号 patch，避免写入模型草稿或其他字段。

归一化规则：缺失、类型错误或非有限数值使用默认 16px；有限数值限制到 14–24px，再按步长 1px 取整数。设置页“应用”分类使用滑块和当前值；范围常量由共享类型模块提供，避免设置页与存储归一化不一致。

保存失败复用自动保存错误提示与读取已保存值的回退方式。不能出现界面声称已保存而下次卡片使用旧值的情况。

备选方案是保存“整个界面缩放百分比”，但这会同时影响图标、输入区和控件，不符合本次以回答阅读为中心的范围。

### 3. 将字号快照随卡片状态传递（已实现，保留）

CardState 已包含用于显示的字号值：主进程创建卡片时从 SettingsStore 读取，窗口初始化和后续 CardState 更新沿用已有通路。只传字号，不向回答窗口发送完整设置，更不传密钥。

卡片恢复、流式更新、重试和追问应使用本会话创建时的字号快照。现有逐轮更新通过展开状态对象发送，因此需保证字号字段也被保留；烟雾测试中的手工 CardState 样例需同步适配。

备选方案是新增独立“设置变化”事件，但本次已确认下次卡片生效，无须引入实时同步通路。

### 4. 回答区域使用局部字体变量（已实现，保留）

只在回答渲染区域使用基于字号参数的 CSS 变量，段落、列表和链接继承正文尺寸。实现采用 h1/h2 为正文的 1.25 倍、h3/h4 为 1.125 倍、h5/h6 为 1 倍，代码与表格为 0.95 倍；正文行高维持 1.8，标题行高 1.45，段落下间距 0.8em，列表缩进和块间距随字号调整。比例是用户授权推荐方向下的实现参数，不扩展到其他界面。

局部变量同时覆盖 Markdown 正式组件和 lazy 加载时的 `.answer` 回退显示，减少加载和流式输出中的字号跳变。代码保持必要的预格式及局部横向滚动，表格保留局部滚动，正文继续折行。

品牌、用户问题标签、输入框和按钮使用独立尺寸，不随回答字号参数整体缩放。输入框固定为 14px，意图标签不再显示。

备选方案是仅修改正文的 `font-size`，但会保留代码和表格的绝对小字号，不能完整支撑回答阅读体验。

### 5. 按已确认清单删除显示，不删除会话数据（已确认行为 + 技术边界）

- 不显示截图时间或意图标签，不删除 CardState.capturedAt 或改变截图、追问语义。
- 删除 Preview 组件与截图入口；截图 image 字段仅用于既有上下文与请求有效性，不创建截图或定位的展示 DOM。
- 输入区去掉 placeholder、发送文字、常驻说明及空白状态说明；动态 notice 仅有内容时显示。
- 首轮自动任务提示不再显示；用户实际输入的问题保留。复制改为悬停或键盘聚焦时可见的图标按钮，保留可访问名称。
- Enter、Shift + Enter、中文输入法组合输入逻辑沿用现有实现。

无需为移除的说明增加新的 tooltip、帮助按钮或常驻解释；这些替代交互没有获得确认。

### 6. 卡片视觉方向（最新草案已确认）

最新方案采用纯白底、既有 Logo 和蓝色图标强调，以留白组织内容：

- 顶部约 56px，左上角保留 Logo 和“PingScreen”，右上角增加仅显示 X 的关闭按钮；无意图标签和设置按钮。品牌与空白部分保留拖动区，X 必须位于不可拖动区域，支持鼠标和键盘操作并具有“关闭”可访问名称。
- 回答区左右留白 24px，段落按字号排版；初始待提问状态保持空白，不放置额外引导文字或图案。
- 底部纯白、无整块灰色背景或分隔横线；输入框高 44px、白底细边框，右侧同一行是 40px 圆形蓝色发送按钮，仅显示向上箭头。
- 生成时同一圆形位置切换为停止图标，保留操作能力；生成指示使用小圆点及可访问状态，避免常驻解释句。
- 卡片外边框改为 2px 浅灰，圆角改为 20px；用户已确认厚度、浅灰方向和圆角数值。具体色值拟采用 `#cbd2dc`，属于可在视觉验收中微调的实现细节，尚不是用户确认的精确色值。代码与表格保持必要结构和白色底，不增加大片灰底容器。
- 错误和复制反馈是按状态出现的必要信息，不在正常空白状态中占据说明行。

X 复用既有 close 命令，与 Esc 一致：关闭整个当前回答会话并中止生成，不能只隐藏窗口而留下请求运行。关闭后的延迟内容或尺寸事件不得重新显示窗口。设置入口继续位于托盘。

验收使用同一固定内容对照上一版 640 × 400 与新版动态卡片，覆盖空白、短回答、连续输出、长 Markdown、追问、停止、失败及复制反馈。默认尺寸预期为初始约 640 × 160、最高 640 × 640；另检查受限宽度及 14/16/24px。截图和验证记录只在后续实现后更新，不能将已有固定尺寸的结果当作本轮通过证据。

### 7. 内容驱动且有上限的窗口高度（已确认行为 + 拟采用技术方案）

所有尺寸采用逻辑像素，与现有 Electron 工作区坐标保持一致：

- 默认宽度 `W = 640`；受限工作区取 `W = min(640, workArea.width)`，不再将宽高按 16:10 同比缩放。
- 高度上限 `Hmax = floor(min(W, workArea.height))`，以实际宽度计算。宽度缩为 320px 时上限为 320px（仍受可用高度限制）；宽度为 640px 但工作区只有 200px 高时，上限为 200px。
- 新会话初始高度 `H0 = min(160, Hmax)`。160px 是用户确认的紧凑基准，不是不可降低的原生最小高度。
- 目标高度为 `min(Hmax, max(H0, 本会话已达到高度, 内容所需高度))`；内容包括顶部、回答自然高度、当前反馈、输入区、留白和边框。不为未显示截图或隐藏首轮任务提示预留高度。
- 同一会话只增高；停止、完成、复制反馈消失及重试导致内容变短时不收缩。追问累计当前会话全部可见内容，新会话重置为紧凑高度。若用户拖动到更小的工作区，工作区可达性约束优先，允许将窗口裁界到新上限。

渲染端拟使用内层自然内容容器与 ResizeObserver，在实际宽度下测量高度；不要以 flex 填充后的滚动区 clientHeight 作为内容高度。包含 Markdown lazy 回退到正式渲染的变化、流式折行、错误与重试区域、复制反馈和当前字号；达到上限后仍测量自然内容，但只让回答区滚动，顶部与输入区保持固定可见。窄屏时按实际宽度重新测量；减少留白以维持必要操作区，不通过超过 W 来容纳内容。

拟复用受校验的命令通路上报所需高度。主进程仅接受来自当前回答窗口、匹配当前会话且有限的高度请求；宽度、上限和位置仍由主进程计算，不接受任意窗口边界。合并连续测量、取整并忽略相同高度，防止每个字符引起原生窗口跳动和测量回环。具体节流间隔作为实现细节，在固定流式样例中确定。

窗口通常保持当前左上角，向下增高；靠近屏幕底部时只按需要上移，避免底部越界。更新根据窗口当前所在显示器的工作区裁界，使用现有窗口位置，不能每次返回最初截图锚点而覆盖用户拖动结果。用户已向上滚动时保留阅读位置；接近底部时沿用跟随最新内容的行为。高度上限仍由宽度决定，不采用屏幕可用高度 70% 或 90% 的方案。

Windows 固定窗口的原生限制会阻止直接改变尺寸。主进程在每次受控尺寸更新期间暂时释放限制、设置边界，并立即恢复不可手工缩放；关闭和新会话切换时清理待处理测量，丢弃旧会话请求。验证必须读取实际窗口边界和不可缩放状态，不能仅检查 CSS 视口。

备选方案是固定 640 × 640 或仅收缩卡片内部 CSS；前者无法体现从矮到高，后者仍保留过大原生窗口和鼠标占位，因此不采用。另一备选为允许随内容反复收缩；用户已确认同一会话只增高，因此不采用。

## Risks / Trade-offs

- [字号增大导致更多换行、可见内容减少] → 在最终最大字号下检查长段落、列表、代码、表格；正文滚动，宽代码/表格局部滚动，输入区不被挤走。
- [删除底部提示时连同反馈一起消失] → 明确区分常驻提示与动态 notice，验证复制成功和操作失败。
- [自动保存误提交模型草稿或快速修改覆盖最终值] → 复用现有提交队列和单字段 patch，测试快速调整、失败回退及草稿隔离。
- [旧配置和手工测试样例缺少字段] → 使用归一化默认值，适配 CardState 样例，并验证旧配置加载；不批量重写用户配置。
- [视觉“更好看”难以客观验收] → 按已确认的 Q4 方向输出相同固定内容和窗口尺寸的前后对照，记录自动排版结果；真实屏幕上的舒适度仍由用户手动验收。
- [设置页打开会结束当前回答] → 此行为已向用户澄清并被接受；在功能说明与验收中保持一致，不承诺保留或实时改变原会话。
- [长回答达到最高 640px 后需要滚动] → 此上限由用户明确选择；在最大字号和长回答下验证正文可达、输入区固定可见，不擅自扩大上限。
- [连续测量与原生窗口调整产生抖动或回环] → 使用自然内容高度、同会话单调增高、合并更新与整数去重，验证流式样例及 Markdown 渲染切换。
- [窗口增高越过屏幕边缘、拖动后被重置或旧会话尺寸污染新卡片] → 主进程按当前工作区及窗口位置裁界，校验会话，覆盖底部锚点、拖动、关闭后延迟事件与新会话复用。

## Migration Plan

本轮仅修订规划；以下步骤留待 openspec-apply-change：

1. 保留已实现的字号、自动保存、会话快照、隐藏截图与空白输入框。
2. 替换共享固定比例几何逻辑，接入受控内容高度测量及主进程窗口调整。
3. 增加 X 关闭按钮，更新边框和圆角；验证拖动与关闭、生成停止、键盘聚焦。
4. 随尺寸任务补充几何与会话校验测试，随界面任务补充实际窗口和各状态集成验证，更新使用说明及本轮验证记录。
5. 保存固定内容前后对照及流式不同阶段截图，复核真实高 DPI 和多显示器体验。回退时可恢复上一版固定尺寸与样式，无须迁移或清空用户设置。

保存方式、重启保留和生效时机已经确认，不再列为未定项。

## Implementation Decisions

- 2026-10-14 用户调用 openspec-apply-change 后，浅灰边框采用 `#cbd2dc`，厚度 2px、圆角 20px；精确色值是实现选择，最终舒适度仍交由用户查看实际截图和桌面体验，不标为用户提前确认的色值。
- 内容高度使用 50ms 合并更新、整数取整与相同高度去重；观察自然内容、顶部、输入区及滚动区尺寸。固定样例覆盖逐段输出和静置，未出现高度回环；不改变初始高度、单会话只增高或等于宽度的上限。
- 窄于等于 360px 时压缩顶部及输入区留白；输入框和 40px 按钮保持原尺寸，正文独立滚动。真实高 DPI 与多显示器体验的待验收项继续保留在 tasks.md。
