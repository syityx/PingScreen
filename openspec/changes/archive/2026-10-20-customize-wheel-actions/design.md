# Design

## Context

动机见 proposal.md。Electron 主进程负责截图、手势会话、配置及模型调用，React 渲染轮盘和设置。第一版已经实现共用六槽位、四／五／六项、按槽位身份命中、框选派生和多个自定义任务；本次改版保留这些能力，将同页列表和编辑表单替换为分级编辑流程。

`SettingsStore` 使用 version 2 配置、服务商 profiles、密钥加密和临时文件替换写入，已能整体保存轮盘。第一版 `WheelEditor` 使用失焦自动保存；本次只改变编辑会话的提交时机。通用截图与预设回答规则、自动 prompt 任务和等待输入的 builtin custom 已在第一版分离，继续沿用。

现有 wheel-presentation 只明确覆盖四／五项，需要增量扩展覆盖范围；settings-interface 的紧凑排版继续适用，轮盘保存方式以本次增量明确为手动保存例外。`docs/plans/2026-10-14-settings-and-shortcuts.md` 提到的轮盘缩放与单击触发仍是其他工作，不随本变更实现。

## Goals / Non-Goals

**Goals:**
- 同一份配置派生预览、绘制、命中和执行身份，避免渲染与主进程各维护一套顺序。
- 用会话快照固定任务及提示词，让早松开、异步截图、重试和追问保持一致。
- 在当前偏好和请求边界内增量扩展，不改截图资源生命周期及传输策略。

**Non-Goals:**
- 不引入可跨槽位引用的独立功能库、提示词模板变量、脚本执行或自定义系统消息编辑器。
- 不修改回答卡片视觉结构、截图标注／细节裁切策略和原生助手协议。

## Decisions

### 1. 六个完整槽位，身份和功能类型分离

保留 `wheelSlots: 4 | 5 | 6` 作为显示项数，新增 `wheelActions` 六元素有序列表。每项有稳定 `id`，以及判别联合：`kind: builtin` 配合现有预设 action，或 `kind: prompt` 配合 name、icon、prompt。现有 builtin custom 仍只表示提问；自动任务使用 prompt 类型，避免隐含等待输入和首轮问题展示逻辑冲突。

自定义功能直接属于槽位，复制或更改另一项不共享可变对象；排序移动整个对象及其 ID。允许重复预设、同名自定义项和相同图标，身份只看 ID。六个槽位固定存在，不引入额外功能库或删除后留下空槽位的状态。名称和提示词去除首尾空白后校验非空；名称最多 20、提示词最多 8000 个 Unicode 码点，前后端共用计数和校验规则。

替代方案：以图标或 action 作为 key 会造成重复项高亮／选择冲突；功能库加引用带来删除引用和同步编辑语义，本次六槽位规模无需承担。

### 2. 统一派生可见列表，几何只返回槽位身份

增加共享 wheel 模块，提供默认配置、图标白名单、校验、可见列表和区域派生列表。手势列表为 `wheelActions.slice(0, wheelSlots)`；区域列表在此基础上过滤所有 builtin region，绝不从后面补项。保存校验前四项至少有一个非 region，保证所有布局均能产生非空后续轮盘；允许重复 region 时也能安全过滤。

命中按实际列表长度计算扇区，返回对应 ID 或 null；主进程和渲染使用同一算法、起始角和列表。手势轮盘支持 4–6，区域派生轮盘支持 1–6，单扇区需使用完整圆环路径处理 SVG 不能以同点画满圆的问题。屏幕边缘中心约束、原始目标附近取消半径保持现有行为。

预览采用同一轮盘绘制逻辑或同源纯展示组件，替代设置中的静态四／五项 SVG。扇区显示图标，附近反馈使用名称；不在六项扇区内强塞文本。

替代方案：仅把项数联合改成包含 6，仍使用固定 ACTIONS，会造成第六项无功能且无法处理自定义顺序；框选继续固定四项会丢失自定义入口。

### 3. 同窗口三级页面与单个编辑会话

主设置页保留四分类连续页面及模型连接草稿，轮盘分类仅显示预览和其右侧编辑按钮。打开后以本地层级状态替换内容区，不创建窗口或标签页；原主页面保持挂载但不可见／不可聚焦，保留滚动位置和连接草稿。二级及三级编辑页隐藏主导航，内容区占满当前窗口；返回主配置页恢复原侧栏状态。二级页顶部返回、项数选择和保存，正文保持左侧预览、右侧六槽位列表；最小窗口缩小预览而不把两列改为上下结构。

进入时深复制已保存轮盘为唯一草稿；三级页、排序及项数均修改该草稿。三级页仅编辑当前槽位名称、内置图标和提示词，完成时校验后返回二级页，不写磁盘；返回可保留未完成输入，再次进入可继续编辑。二级页保存校验所有槽位，原子提交完整轮盘并更新生效基线。失败保留草稿并显示错误，不回退输入，不提交模型连接草稿；保存中禁止编辑与重复提交。实际手势继续使用最后成功保存的轮盘。

二级页返回主配置页、任一级编辑页切换左侧分类或关闭设置窗口时，若草稿与生效基线不同，出现保存并退出／不保存退出／取消弹窗。保存失败或校验失败不得退出；不保存恢复基线；取消保留页面、草稿与焦点。三级页完成或返回仅在编辑会话内部移动，不算退出。主进程窗口关闭事件先通知设置渲染器，由同一离开守卫确认后再隐藏窗口；应用主动退出仍遵循现有退出流程。

替代方案：上一版同行编辑、失焦自动保存不再适用；独立新窗口不能保留连续的预览过渡和导航体验。

### 3a. 排序与聚焦编辑互相独立

每行显示序号、图标、名称和隐藏标记，右侧只有编辑与 3×3 实心小方块拖动手柄。左键按住手柄采用 Pointer Events、指针捕获和行中心命中拖动排序，临近列表边缘自动滚动，预览同步更新；使用布局前后矩形的 FLIP 位移动画使被换位的行平滑滑动，命中计算使用稳定的 offsetTop 和 offsetHeight，避免动画改变命中导致抖动。取消拖动恢复拖动前顺序。键盘聚焦手柄后使用方向键调整同一槽位，提供可访问名称与顺序反馈，不增加额外上下移按钮。

只有点击编辑按钮才进入聚焦状态：选中行小幅放大并与功能菜单保持清晰，其余内容背景虚化且不能操作。聚焦层在侧栏之上，点击背景或 Esc 关闭并恢复编辑按钮焦点；选项为解释、翻译、改写、提问、框选、自定义。预设更新草稿后关闭聚焦；自定义进入三级页。长按行、点击预览及开始拖动均不触发聚焦。

### 3b. 预览过渡与可访问性

采用现有 SVG Wheel 作为共同视图，用元素实际矩形计算反向位移与缩放（FLIP），在两个页面之间动画过渡。返回时也使用当前位置和尺寸计算，避免更改项数、滚动或窗口尺寸后跳动。快速导航取消旧动画，尊重 prefers-reduced-motion，页面切换和排序均可直接到达最终状态。三级页名称和提示词输入框聚焦保持中性灰边框，不显示蓝色边线、外轮廓或光晕。聚焦和退出弹窗具备键盘焦点约束与恢复、明确标题和 Esc 行为，背景不可交互。

### 4. 主进程决定执行内容，会话保存快照

wheelOpen 时深复制完整有效轮盘及当前可见列表至 Session，StageState 发送绘制需要的 ID、名称、图标、类型和派生顺序，不必发送提示词正文。松开或框选后的点击仅提交槽位 ID；主进程从当前会话当前阶段可选列表解析，不接受渲染提交任意提示词或隐藏槽位 ID。

选中功能后存储已解析的任务快照。builtin region 进入现有框选流程；builtin custom 打开等待输入的卡片；其他 builtin 按原流程生成首轮短指令；prompt 直接用保存文本请求。卡片以明确的任务类型或首轮来源区分自动任务与用户问题，自动首轮隐藏，手动提问及追问显示。无需展示自定义任务标签或修改现有卡片排版。

翻译范围判断基于被选项的 builtin translate 类型，不能按图标／名称判断；进入翻译、离开翻译、早松开及区域模式仍遵循现有重置规则。若存在多个翻译槽位，在其间切换按槽位切换重置范围，防止旧滚轮状态泄漏。打开设置仍结束会话。

替代方案：执行时重新读取配置会使截图等待期间或后续重试任务漂移；按数组下标接受任意命令容易把排序或区域过滤后的项解释错误。

### 5. 拆分通用规则和预设风格，传输不变

在 model.ts 将系统提示词拆为通用截图规则与预设默认规则。通用部分包含定位坐标、标注、全屏及细节图、历史快照、不确定性、截图内容作为资料及不声称已操作应用，不附加中文／短回答／Markdown 偏好。builtin 路径组合原有效默认规则，保持现有解释、翻译、改写及提问行为；prompt 路径只使用通用部分，以用户保存文本作为首轮任务，不附加 TRANSLATION_PROMPTS。

继续使用 messagesFor 的图片、目标和轮次结构、askModel 的服务商连接及传输；后续请求从 Session 的任务快照选择规则，沿用已有历史裁剪、同一画面、停止和重试。用户后续问题可细化任务，首轮提示词不会每次作为新追问重复追加。现有模型单测关于 SYSTEM 默认行为的断言保留于 builtin 路径，并增加对自定义请求边界的验证；不以模型是否逐字服从作为确定性测试条件。

替代方案：只替换 PROMPTS 文本但沿用整个 SYSTEM，会让用户的英文、长文或 JSON 要求受到预设风格干扰；允许编辑完整系统消息则暴露过多内部定位职责。

### 6. 向后兼容的加载与严格保存

继续使用外层 version 2 和现有 profiles／加密结构，新增 wheelActions 字段，不扩大配置版本以免旧版把新文件误判为 legacy 而丢失 profiles。缺少该字段时构造六个稳定 ID 的默认项：解释、翻译、改写、提问、框选、解释；第六项作为有效可替换默认值，默认五项使旧用户看不到新增重复项。该第六项默认与字段长度、图标初选均为本提案的小范围默认决策。

加载容错：非六项列表回退整套默认；六项列表中的损坏项按同位置默认修复，重复／无效 ID 重新生成；未知图标回退 custom 图标；修复后若前四项仍全是 region，则回退默认。合法的其他槽位尽量保留。读入不写盘，第一次保存新轮盘字段前备份旧设置文件，之后沿用临时文件和原子替换。get/public 返回的嵌套轮盘数据不得共享可变引用。

保存严格：对来自 IPC 的完整轮盘偏好检查项数、列表结构、ID 唯一性、功能、字段长度、图标及非空派生轮盘；拒绝无效写入，不静默改成其他有效任务。加载修复与保存拒绝分离，避免错误配置被表现为保存成功。

## Risks / Trade-offs

- [六项及较少项区域轮盘的扇区变化可能选错] → 统一派生和命中；覆盖 1–6 项角度、边界、中心与屏幕边缘，真实渲染校验单扇区。
- [编辑与生效配置混淆] → 单一草稿和成功保存基线；失焦、完成、拖动均不写盘，保存失败不得退出。
- [拖动、聚焦及过渡叠加] → 手柄专用排序、编辑按钮专用聚焦；指针取消恢复，页面切换时终止旧动画。
- [自定义输出格式受旧默认规则污染] → 将通用／预设规则明确拆分，在实际发送报文上验证英文、长回答和 JSON 要求的上下文。
- [重复图标、名称和预设导致执行身份混淆] → 稳定 ID 贯穿预览、命中、IPC 和 Session，以重复项作为集成场景。
- [模型可能无法严格遵循用户输出要求] → 验证请求内容和分流正确性，不承诺模型无法保证的格式服从率。
- [旧程序再次保存会丢弃不认识的新槽位字段] → 保留升级前备份；降级恢复备份，不承诺双向混用版本后仍保留新功能。

## Migration Plan

1. 增加共享槽位模型、默认与校验逻辑，适配配置加载／保存，验证旧 version 1、version 2 和无配置情况。
2. 适配会话、Stage、IPC 和几何后接入动态绘制、设置编辑器及提示词分流；所有改动作为同一功能发布，避免部分升级状态。
3. 完成单元、构建和 Electron smoke 验证，检查配置页面最小尺寸及真实请求报文。
4. 升级首次读取只在内存补齐槽位；用户首次保存新配置时先备份，再原子写入。若需回退，退出应用，恢复升级前备份后运行旧版；其他连接及密钥结构保持原格式。
